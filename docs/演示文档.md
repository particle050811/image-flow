# image-flow 功能梳理

![alt text](Comfyui.png)
先说说 AI 绘图工具的现状。ComfyUI 是为了本地模型工作流设计的，还包含一堆Python的依赖嗯，占空间，启动慢，并且管理提示词很麻烦。而现在的云端商业模型远远强于本地部署的开源模型，并且大部分人是没有本地部署的条件的。对于我这种调用banana/gpt-image2绘图的场景，有点大材小用。
像 Cherry Studio 这类工具界面又太简陋，提示词也不好管理。而 AI 生图最大的工作量恰恰就在两件事上——写提示词和抽卡任务管理，市面上却没有专门解决这两点的软件。所以我做了这样一个 VS Code 插件。

那为什么是做 VS Code 插件，而不是做一个 WebUI？主要原因是 VS Code 插件可以直接复用编辑器自带的文件管理系统，省去在 WebUI 里再实现一套。并且文件实时同步，本地P完图不用重新上传一遍。还能接入其他插件，比如借助 Claude Code 直接写提示词。

### 1. 侧栏工作台(活动栏 Webview,四标签页)

在 VS Code 活动栏注册独立图标 "Image Flow",点开是一个 React 单页,分四个标签:

| 标签 | 作用 |
|------|------|
| **工作台** | 配置生成参数、触发生成、查看结果与素材库 |
| **编辑** | 上传/拖入图片做图生图改写 |
| **任务** | 进行中任务 + 历史任务统一管理 |
| **设置** | API Key、节点地址、模型注入句等配置 |

### 2. Markdown 一键生成(文生图 / 图生图)

- **右键菜单触发**:在任意 `.md` 文件(资源管理器或编辑器内)右键 → "生成 AI 图片" / "预览请求"。
- **正文图片解析做图生图**:自动把 Markdown 正文里的 `![](路径)` 解析为**有序参考图**(转 base64),并替换为 `[image1]`、`[image2]` 等引用,实现"以文档里的图为参考"的图生图。
- **预览请求**:生成前可先预览最终发送给 API 的完整请求体,便于核对。

### 3. 提示词智能注入

最终发给模型的 prompt 由三段拼成:

1. **模型注入句** —— 每个模型有内置兜底句,可在设置里覆盖;
2. **工作区根 IMAGES.md** —— 全局风格/约束;
3. **文档正文**。

### 4. 图片编辑页(图生图改写)

- 支持**上传 / 拖入**图片,做独立参数的图生图改写。
- 编辑页有**专属参数**(模型 / 比例 / 分辨率 / 并发),与主生成界面互不影响。
- 提供**提示词模板**:扫描 `.image-flow/prompts/` 下的 `.md` 模板供快速套用。
- 编辑区图片列表由主进程持有,Webview 重建不丢数据;大图自动生成压缩展示图。

### 5. 异步任务机制(项目核心亮点)

完整的"**异步提交 + 后台轮询 + 重启续拉**"任务系统:

- 点生成 → 立即在 `.image-flow/tasks/<毫秒时间戳>/` 建任务文件夹,**秒级建卡返回**,不干等网络;
- 按并发数**并发提交**多个 job 拿远端 id;
- 任务记录持久化进 `globalState`;
- 单个定时器(4 秒)**轮询查询结果**,某 job 成功就下载图片入文件夹;
- 全部 job 终结后从持久化移除(无成图则连空文件夹一并删除);
- **重启 VS Code 自动续拉**未完成任务(`onStartupFinished` 激活);
- 任务卡片显示**实时进度、已进行时间、来源 MD 文件名**。

### 6. 任务归档与可追溯

每个任务统一落盘到 `.image-flow/tasks/`,文件夹内归档:

- 完整提示词 `.md`(生成=来源 md 名,编辑=edit);
- `input/` 参考图原图;
- 生成结果图片。

做到每张图都能追溯到当时的提示词和参考图。

### 7. 素材库

- **手动素材库**:添加任意文件夹,递归扫描出图片展示;
- **自动素材库**:按 MD 路径自动生成;
- 缩略图尺寸**可调**(每行显示张数可配);
- **同名 MD 描述联动**:图片若有同主名 `.md` 描述文件,排序靠前,插入引用时附带描述进正文;
- 图片可**左键打开查看、右键插入引用**,编辑区/素材库/任务页交互一致。

### 8. 缩略图性能优化

- Webview 端生成缩略图并回传落盘缓存(避免重复加载大图);
- 真缩略图 + 编辑区压缩展示图,降低内存与缓存膨胀。
