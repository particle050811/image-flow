# 图片编辑功能设计规格

日期：2026-06-10
状态：待评审

## 1. 概述

为 image-flow 侧栏新增「编辑」标签页：上传/拖入参考图，配合预设提示词模板编辑提示词，用独立于主生成界面的模型参数提交图生图任务。同时把所有任务产物（生成 + 编辑）统一存储到工作区根 `.image-flow/` 下，并为任务补充「查看提交的提示词」与「一键送编辑」能力。

## 2. 目录与数据布局（统一存储）

```
<工作区根>/.image-flow/
├── prompts/                            # 预设提示词模板
│   ├── 三图合并漫画.md                  # 文件名（去扩展名）= 模板名
│   └── 生成三视图.md                    # 文件内容 = 提示词原文（无 frontmatter）
└── tasks/                              # 所有任务（生成 + 编辑，扁平）
    ├── 260610153000123/                # <yyMMddHHmmssSSS>（毫秒级时间戳，无前缀无 seq）
    │   ├── 角色设定.md                 # 提示词文件，文件名沿用来源 md 名；头部记来源路径
    │   ├── input/                      # 提交时的参考图归档，按引用序号命名
    │   │   ├── image1-猫.png           # 对应提示词文件里的 [image1]
    │   │   └── image2-狗.png
    │   └── 角色设定-1.png              # 图片名前缀 = md 名（生成任务）
    └── 260610153512456/
        ├── edit.md                     # 编辑任务无来源 md，提示词文件名固定 edit.md
        ├── input/
        │   └── image1-原图.png
        └── edit-1.png                  # 图片名前缀 = edit（编辑任务）
```

- **统一任务目录**：生成与编辑任务同存 `.image-flow/tasks/`，不分子目录；来源通过文件夹内图片名前缀（md 名 / `edit`）即可辨认。
- **生成任务迁址**：`createTaskFolder` 不再建在 Markdown 同级，改建在 `.image-flow/tasks/`；文件夹名就是毫秒级时间戳，`task-` 前缀与 `-seq` 后缀均去掉（目录已专用，无需前缀区分）。
- **旧数据**：散落在各 md 同级的旧 `task-*` 文件夹不扫描、不迁移、不展示，由用户自行处理。
- **参考图归档**：提交时把本次使用的参考图复制进任务文件夹 `input/` 子目录，命名 `image<N>-<原名>`，与提示词文件中的 `[imageN]` 一一对应，任务自包含可复现；生成任务（md 引用图）与编辑任务行为一致。
- **提示词文件**：生成任务沿用来源 md 的文件名（如 `角色设定.md`），编辑任务固定 `edit.md`；frontmatter 记元信息——生成任务记来源 md 的工作区相对路径（`source: 角色/角色设定.md`），编辑任务记 `source: （编辑任务）`；正文为提交的最终提示词。便于事后追溯任务出处。
- **历史扫描**：`listHistory` 不再依赖当前活动 md，统一扫 `tasks/` 一个目录，按文件夹名中的时间戳倒序。`.md` 文件非图片、`input/` 是子目录，现有「仅收文件 + 图片白名单」的非递归扫描天然忽略两者，任务卡片只显示产出图。
- **无工作区文件夹**时，生成与编辑均报错提示不可用。

## 3. 预设提示词模板

- 每模板一个 `.md` 文件，放在 `.image-flow/prompts/`，文件名即下拉框中的模板名，文件全文即提示词，无 frontmatter。
- 编辑页提供模板下拉框；选中后把模板内容**追加到提示词框末尾**（不覆盖已有内容），之后可自由编辑。
- 切到编辑 tab 时刷新模板列表；目录不存在或为空时下拉为空并提示去 `.image-flow/prompts/` 创建。

## 4. 编辑标签页 UI

新增第 4 个 tab「编辑」，置于「任务」之前。自上而下：

1. **图片区**：已上传图缩略图网格。每张图角标显示当前序号 N（即提交时的 imageN）、hover 显示删除按钮。**点击图片**在提示词框光标处插入 `![](文件名)`。
2. **模板行**：模板下拉框（见第 3 节）。
3. **提示词框**：多行 textarea。
4. **参数行**：模型 / 分辨率 / 比例 / 并发，绑定 4 个新配置字段（见第 6 节）。
5. **生成按钮**：提交编辑任务（见第 5 节）；旁边复用「预览请求」逻辑展示最终提示词与参数。

### 生成按钮冷却

主界面与编辑页的两个生成按钮，点击后前端禁用 0.5 秒，防止连点重复提交。

### 图片来源（三种）

| 来源 | 机制 |
|---|---|
| 上传按钮 | `vscode.window.showOpenDialog`（图片扩展名过滤、可多选） |
| 侧栏内拖拽 | 素材库 / 任务页缩略图设为 draggable，dataTransfer 携带图片 file uri，编辑页图片区接收 |
| 资源管理器 / 系统拖入 | drop 事件优先读 `text/uri-list` 取文件路径；拿不到路径时读 File 二进制，由扩展**存内存**（base64），不落盘 |

- 编辑区图片统一读成 data URI 驻留扩展内存、不预先落盘复制——图片可能来自 `localResourceRoots` 之外的任意目录，data URI 是 webview 唯一可靠的展示方式，且提交时本就要转 base64，无重复开销。代价是扩展重启后编辑区清空，可接受。提交时所有参考图统一归档进任务文件夹 `input/`（见第 2 节）。
- 已上传图片列表由**扩展主进程持有**，webview 重建后不丢；前端通过消息增删，扩展推送带 `asWebviewUri` src（内存图用 data URI）的列表。
- 文件名与已上传图片重名时拒绝添加，状态栏报错提示，由用户改名后再传。

### 图片引用格式

- 插入格式：`![](文件名)`，与 Markdown 生成管线同一语法。
- 提交时复用现有 `replaceImageRefs`：以**图片区顺序**建立 文件名→N 映射，把文本中的 `![](文件名)` 替换为 `[imageN](文件名去扩展名)`。
- 参考图按图片区顺序全部发送（未在文本中引用的也发送）。
- 删除图片不改写提示词文本；提交时若文本引用了已删除的图片名，报错中止并指出名字。

## 5. 提交与任务机制

- `PendingTask` 增加 `kind: 'generate' | 'edit'`；文件夹定位从「mdUri 相对」改为由工作区根 `.image-flow/tasks/` 推导（生成任务仍记录 mdUri 用于图片名前缀等）。
- `TaskManager` 新增 `submitEdit(prompt, images)`：读编辑专属配置 → 按图片区顺序把图片读成 base64（内存图直接取）→ 替换引用 → 建 `tasks/<时间戳>` 文件夹 → 写提示词文件（`edit.md`）+ 归档参考图到 `input/` → 按 `editConcurrency` 并发提交，后续轮询/下载/续拉/超时逻辑全部复用现有链路。
- **失败清理**：现有「无产出任务删除整个文件夹」的清理行为保留——全失败任务的提示词文件与 `input/` 归档随文件夹一并删除。
- 编辑提示词走 `buildInjectedPrompt` 的**模型注入句**（按 editModel 取），但**不拼接工作区根 IMAGES.md**。
- 生成任务的 `submit` 同步改动：落新目录、提交时写提示词文件（沿用来源 md 文件名）。
- 编辑任务产图文件名前缀用 `edit`。

## 6. 配置

`ImageFlowConfig` 新增 4 个编辑专属字段，与主界面字段互不影响：

- `editModel` / `editImageSize` / `editAspectRatio` / `editConcurrency`
- 初始默认值与主配置字段的默认值相同；可选项复用现有 `ConfigOptions`。

## 7. 任务页改动

- 编辑任务与生成任务共用任务页（进行中卡片 + 历史列表），不做来源标注（图片名前缀已可辨认）。
- 每张缩略图 hover 时右上角显示「✎」按钮：点击把该图加入编辑页图片区并自动切到编辑 tab（不清空已有图片，追加）。
- 卡片展开区加「查看提示词」按钮：在编辑器中打开该任务文件夹内唯一的 `.md` 提示词文件（文件名不固定，按扩展名查找）；找不到时提示不存在。

## 8. 消息协议（src/shared.ts 增量）

扩展 → 前端：

- `promptTemplates`：模板列表 `{ name, content }[]`
- `editImages`：编辑区图片列表（带 src 与显示名）

前端 → 扩展：

- `editUpload`（弹文件选择器）
- `editAddImages { uris }`（拖入的 uri-list / 任务页 ✎ 按钮）
- `editAddImageData { name, base64 }`（二进制拖入兜底，扩展存内存）
- `editRemoveImage { uri }`
- `editGenerate { prompt }`
- `openPrompt { folder }`（打开任务文件夹内的提示词 .md 文件）
- `refreshTemplates`

## 9. 错误处理

- 无工作区文件夹：编辑页与生成按钮提示不可用。
- 提示词为空或引用已删除图片：提交前校验报错，不建任务。
- 参考图读取失败：沿用现有「列出失败文件并中止」行为。
- 模板读取失败：状态栏提示，不影响其余功能。

## 10. 测试要点

- 纯函数单测：文件名→序号映射 + `replaceImageRefs` 在编辑场景的替换；重名拒绝；引用已删图片的校验。
- 现有测试调整：`createTaskFolder` / `listHistory` 路径与签名变化、时间戳毫秒化去 seq。
- 模板扫描：空目录 / 不存在目录 / 非 .md 文件忽略。

## 11. 不做的事（YAGNI）

- 不自动迁移旧 task-* 文件夹。
- 删图时不自动改写提示词文本。
- 模板不做 frontmatter / 分类 / 内置默认模板。
- 不做编辑任务专属的历史页。
