# 提示词引用替换重构 设计

日期：2026-06-26

## 背景与目标

当前替换链路有两套并行实现，语义割裂、且产物格式不符合需求：

- **生成链路**（`command.ts`）：把 `![alt](路径)` 替换为 `[imageN](文件名)`，按出现顺序编号、读图当参考图。
- **编辑链路**（`edit.ts` 的 `buildEditPrompt`）：把 `![](文件名)` 替换为 `[imageN]`，编号按编辑区图片顺序（非正文顺序）。

本次重构目标：

1. 替换产物改为**即梦格式** `【@图片N】`（依据 `docs/演示文档/演示要点.md` 6.24 想法「兼容即梦格式」）。
2. 引入「**命名引用**」概念：正文里的 `[名字]` 若对应一张已声明的媒体，则替换为 `【@图片N】`/`【@音频N】`/`【@视频N】`。
3. 媒体声明语法 `![alt](路径)` 本身从发给模型的正文里**删除**，但媒体仍作参考图上传。
4. **编辑页复用生成链路**：编辑页正文改写成与工作台 MD 完全一致的形式，删掉独立的 `buildEditPrompt`，生成与编辑只剩一套替换逻辑。

## 替换规则（最终）

新的替换只作用于**发给模型的 prompt**。归档正文（`archiveImageRefs`/`buildEditArchivePrompt`）和参考图读盘/上传逻辑**不变**。

### 1. 媒体声明（编号来源）

- 语法 `![alt](路径)`，取 **alt 文本**作为「名字」。
- 按**首次出现顺序**编号；媒体类型（图片/音频/视频）由路径扩展名区分，**三类各自独立计数**。
- 同一类型内**禁止同名**：两处声明同名 alt → 抛错中止（替换前校验）。
- 该声明语法在发给模型的正文里**整体删除**（只删 `![...](...)` 本身，前后空格/标点保留）。
- 媒体本体照常读盘转 base64，按声明顺序作参考图上传。

### 2. 命名引用（正文中的 `[名字]`）

- 正文里凡 `[名字]`，若「名字」命中某类型的声明名字表 → 替换为 `【@图片N】`/`【@音频N】`/`【@视频N】`（N 为该名字在对应类型里的序号，阿拉伯数字）。
- 未命中的 `[名字]`（如 `[魂符]`、`[李樱]`）→ **原样保留**。

### 3. 媒体类型判定

- 图片：现有 `isImageExt` 白名单。
- 音频/视频：新增扩展名白名单（音频 mp3/wav/...，视频 mp4/mov/...）。具体清单实现时定，先覆盖常见格式。

## 编辑页改造（复用生成链路）

核心：让编辑页正文变成工作台 MD 格式，然后走同一个新替换函数。

1. **右键插入引用**（`Edit.tsx`）：从插入 `![](文件名)`（`imageRefSnippet`）改为只插 **`[图片名]`** 命名引用（中括号）。
2. **提交/预览时**（`tasks.submitEdit` / `sidebarProvider.doEditPreview`）：在「编辑模型注入句之后、用户正文之前」自动插入**编辑区全部图**的声明行——每张图一行 `![图片名](文件名)`，顺序为编辑区顺序。
   - 拼出的正文 = 顶部声明区 + 用户正文（含 `[图片名]` 命名引用）= 工作台 MD 格式。
   - 「全部图都声明」保留现有「编辑区图片整体按序上传」语义：即使某图正文未引用，仍作参考图上传，只是正文无对应 `【@图片N】` 文字。
3. 删掉 `buildEditPrompt`；`buildEditFinalPrompt` 改为「拼注入句 + 声明区，再走新替换函数」。
4. `buildEditArchivePrompt` / `archiveImageRefs` **不动**（归档仍是可右键重生成的 `![](input/原名)` 形式）。

## 受影响文件

- `src/command.ts`：新增替换函数（声明删除 + 命名引用 + 三类编号 + 同名校验）；`buildPrompt` 改用之。
- `src/refs.ts`：可能新增「命名引用片段」纯函数 `[名]`（供编辑页右键插入），与 `imageRefSnippet` 并列。
- `src/images.ts`：新增音频/视频扩展名判定。
- `src/edit.ts`：删 `buildEditPrompt`；`buildEditFinalPrompt` 改为拼声明区 + 复用新替换。
- `src/webview/Edit.tsx`：右键插入改为命名引用。
- `src/tasks.ts` / `src/sidebarProvider.ts`：编辑提交/预览传入「编辑区全部图」用于声明区拼接。
- `src/test/logic.test.ts`：重写 `replaceImageRefs`/`buildEditPrompt` 相关用例为新规则。

## 样例

### 生成链路（右键 MD）

输入：
```
- [传送石] 传送道具，手持物品。![传送石](./传送石.png)
[李樱]一手持[传送石]，一手持[魂符]
![开场曲](./bgm.mp3) 配乐用[开场曲]
```

发给模型的 prompt（注入句略）：
```
- 【@图片1】 传送道具，手持物品。
[李樱]一手持【@图片1】，一手持[魂符]
 配乐用【@音频1】
```
参考图上传：传送石.png（image1）、bgm.mp3（音频1）。
- 声明语法 `![传送石](...)`、`![开场曲](...)` 整体删除（前后空格保留 → 行尾留空格、行首留空格）。
- `[传送石]` → `【@图片1】`，`[开场曲]` → `【@音频1】`。
- `[魂符]`、`[李樱]` 未声明 → 保留。

### 编辑页

编辑区图片：`猫.png`、`狗.png`（顺序）。用户正文（右键插入命名引用后）：
```
把[狗]放进[猫]的场景
```

提交时拼成（注入句之后）：
```
![猫](猫.png)
![狗](狗.png)
把[狗]放进[猫]的场景
```

走新替换 → 发给模型：
```


把【@图片2】放进【@图片1】的场景
```
参考图上传：猫.png（image1）、狗.png（image2），按编辑区顺序。
